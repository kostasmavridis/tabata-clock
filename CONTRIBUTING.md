## Prerequisites

| Tool | Minimum version | Notes |
|---|---|---|
| JDK | 17 | Must be on `PATH` or set as `JAVA_HOME` |
| Android SDK | 36 | Install via Android Studio or `sdkmanager` |
| Python | 3.8+ | Only stdlib used — no pip installs needed |
| Gradle | 9.5.1 | Auto-downloaded by the wrapper |
| Android Studio | Meerkat 2025.1+ | Optional but recommended |

## First-time setup

```bash
# 1. Clone
git clone https://github.com/kostasmavridis/tabata-clock.git
cd tabata-clock

# 2. Generate the WAV sound files (res/raw/ is git-ignored)
python scripts/generate_sounds.py

# 3. Bootstrap the Gradle wrapper JAR
#    (the .jar cannot be committed via the GitHub API — it must be generated locally)
gradle wrapper --gradle-version 9.5.1 --distribution-type bin

# 4. Verify everything builds
./gradlew assembleDebug
```

> **Windows users:** use `gradlew.bat` instead of `./gradlew`, and `python` or `py` depending on your installation.

## Building the project

```bash
# Debug APK
./gradlew assembleDebug

# Release APK (requires signing config — see README for secrets setup)
./gradlew assembleRelease

# Clean build
./gradlew clean assembleDebug
```

The output APK is written to `app/build/outputs/apk/debug/app-debug.apk`.

## Running tests

```bash
# Run all unit tests
./gradlew test

# Run tests and generate an HTML coverage report
./gradlew koverHtmlReport

# Open the report
open app/build/reports/kover/html/index.html       # macOS / Linux
start app\build\reports\kover\html\index.html      # Windows

# Run a single test class
./gradlew test --tests "com.kostasmavridis.tabataclock.TabataViewModelTest"
```

All 26 tests must pass before a PR can be merged.

## Code style & conventions

- **Kotlin** only — no Java source files in `app/src/main/`
- **4-space indentation**, no tabs
- Follow the [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html)
- Keep functions short and focused — extract private helpers rather than writing long functions
- Use **`data class`** for pure value types; avoid mutable state in models
- Prefer **`StateFlow`** over `LiveData` for observable state
- All public interfaces and classes should have a KDoc comment explaining their purpose

## Project conventions

### Stable releases only
All dependencies and plugins must be at a **stable release** version. Alpha, beta, RC,
preview, and dev versions are never used in this project — not on `main`, not on feature
branches. When evaluating an upgrade, only consider the latest stable release. If no stable
release is available yet, the upgrade waits.

### Interfaces first
Every Android-dependent class (`SoundManager`, `SettingsRepository`, `TabataForegroundService`) is accessed through an interface (`ISoundManager`, `ISettingsRepository`, `ServiceNotifier`). This keeps `TabataViewModel` free of Android framework imports and makes it fully unit-testable.

### Fake implementations for tests
Do **not** use Mockito or MockK to mock interfaces that have simple behaviour. Instead, write a `Fake` class in `src/test/` that implements the interface directly:

```
FakeSoundManager.kt         ← implements ISoundManager
FakeSettingsRepository.kt   ← implements ISettingsRepository
```

Fakes are more readable, faster to execute, and easier to assert on (e.g. `sound.beepCount`).

### Virtual time in tests
All timer-related tests use `StandardTestDispatcher` + `advanceTimeBy()`. Never use `Thread.sleep()` or `delay()` in tests. A full 13-second Tabata cycle should complete in under 1 ms in tests.

### Sound files
The four WAV files in `app/src/main/res/raw/` are **git-ignored**. They are generated by `scripts/generate_sounds.py` at build time (both locally and in CI). Do not commit binary WAV files.

### Gradle wrapper JAR
The `gradle/wrapper/gradle-wrapper.jar` is also **git-ignored** because the GitHub Contents API silently corrupts binary files. CI regenerates it via `gradle wrapper`. Locally, run `gradle wrapper --gradle-version 9.5.1 --distribution-type bin` once after cloning.

### Gradle binary SHA-256 verification
All three CI workflows (`build.yml`, `release.yml`, `codeql.yml`) verify the SHA-256 of
the downloaded Gradle distribution before executing it. This prevents MITM or CDN
tampering from silently running a malicious build tool.

> ⚠️ **Action required when bumping `GRADLE_VERSION`:** update the `EXPECTED_SHA256`
> variable in the bootstrap step of **all three workflows** at the same time. The correct
> hash for each release is listed under **"checksums"** at
> <https://gradle.org/releases/>. Updating the version without updating the hash will
> cause every CI run to fail with `sha256sum: WARNING: 1 computed checksum did NOT match`.

### AGP 9 built-in Kotlin
This project uses **AGP 9.1.1** with built-in Kotlin support (default since AGP 9.0). The `org.jetbrains.kotlin.android` plugin is **not applied** — AGP owns Kotlin compilation. The `org.jetbrains.kotlin.plugin.compose` plugin is still applied explicitly as AGP does not auto-wire the Compose compiler. Do not add `kotlin("android")` to any build file.

### No hardcoded durations in tests
Use `fastSettings.prepareSecs * 1_000L` rather than `3_000L`. If the test settings change, all time calculations stay correct automatically.

## Submitting a pull request

1. **Branch** off `main`: `git checkout -b feature/your-feature-name`
2. **Make your changes** with clear, focused commits
3. **Add or update tests** — coverage should not decrease
4. **Run the full test suite** locally: `./gradlew test`
5. **Push** and open a PR against `main`
6. The CI pipeline will run automatically — all checks must be green
7. A maintainer will review within a few days

### PR checklist

- [ ] All 26 existing tests pass (`./gradlew test`)
- [ ] New behaviour is covered by tests
- [ ] No new lint warnings introduced
- [ ] `scripts/generate_sounds.py` was run if sound files are relevant
- [ ] Commit messages are descriptive (`feat:`, `fix:`, `test:`, `docs:`, `ci:` prefixes)
- [ ] All dependency versions used are **stable releases** (no alpha/beta/RC/preview)
- [ ] If `GRADLE_VERSION` was bumped, `EXPECTED_SHA256` has been updated in **all three**
  workflow files (`build.yml`, `release.yml`, `codeql.yml`) using the hash from
  <https://gradle.org/releases/> (binary-only `-bin` ZIP checksum)

## Reporting bugs

Open a [GitHub Issue](https://github.com/kostasmavridis/tabata-clock/issues) and include:

- Android version and device model
- Steps to reproduce
- Expected vs actual behaviour
- Logcat output if available (filter by `TabataClock`)
